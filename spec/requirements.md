# 要件（WHY）

「なぜその仕様にしたか」の根。各要件に **安定ID `R-n`** を振り、spec / behavior 側から `satisfies R-n` で参照する。
実装中に変わってよい（非ウォーターフォール）。変更時は `decisions/` に理由を残し、波及を `STATUS.md` に起票する。

## 背景・課題

- 家族（ママ・長男・次男）の予定（習い事・学校行事・通院・仕事など）がバラバラに管理されていて、全体を一目で把握しにくい。
- 毎週の習い事のような**定期的な予定**が多い一方、祝日・長期休み・急な休みで**例外的にお休み**になる日がある。
- 主に使うのは**ママ**。スマホ（Pixel 10）の操作に詳しくないため、既存の多機能カレンダーアプリは「どこを触ればいいか分からない」「字が小さい」が障壁になる。
- 複雑な機能は要らない。**見やすく・迷わず・すぐ書ける**ことが最優先。

## ユーザー価値

- **ママ**：スマホのホーム画面のアイコンをタップするだけで、家族全員の予定が大きな字で見える。
  「＋ 予定」→ 入力 → 「保存する」の少ない手順で登録でき、くりかえし予定の「この日だけお休み」もワンタップ。
- **パパ（Ken）**：PC やスマホのブラウザから同じ予定を見られ、必要なら編集もできる。
- **家族**：子どもごとに色分けされているので、誰の予定かが一目で分かる。

|---|---|---|---|
| R-1 | メンバー（初期値：ママ・長男・次男）ごとに予定を登録できる。1つの予定に複数メンバーを指定できる（全員なら「みんな」表示） | must | draft |
| R-2 | 全員の予定を1画面で一覧でき、メンバーを選んで絞り込める | must | draft |

| R-4 | くりかえし予定を登録できる：毎日／毎週（曜日を複数選択可）／2週ごと／毎月（日付 or 第n曜日）／毎年。終わりの日を指定できる | must | draft |

| R-6 | Pixel 10（Android / Chrome）で閲覧・編集できる。ホーム画面に追加してアプリのように1タップで起動できる | must | draft |

## 品質特性（NFR）

| ID | 観点 | 目標 |
|---|---|---|
| R-10 | 操作しやすさ | タップできる部品は 48px 四方以上。基本の文字は 17px 以上。ボタンはアイコンだけにせず日本語ラベルを付ける。予定追加は「＋ 予定 → 入力 → 保存する」の 3 ステップ。Android の「戻る」でアプリが閉じず、開いている画面だけが閉じる |
| R-11 | 見やすさ | メンバーは色＋名前で区別（色だけに頼らない）。日曜・祝日は赤、土曜は青。今日がひと目で分かる |
| R-12 | 性能 | 起動から予定表示まで 1 秒以内（端末内のキャッシュから即表示し、裏で同期） |
| R-13 | オフライン | 電波がなくても閲覧・編集でき、つながったら自動で同期する |
| R-14 | データ保全 | 2 台で同時に編集しても予定が消えない（予定単位でマージ）。変更履歴は git に残り、過去の状態に戻せる |
| R-15 | プライバシー | 予定データは非公開リポジトリだけに置く。公開リポジトリ（アプリ本体）に個人情報・トークンを含めない。トークンはデータ用リポジトリ 1 つだけに限定した権限にする |
| R-16 | 費用 | 無料（GitHub Free の範囲）。サーバー・有料サービスを使わない |
| R-17 | 保守性 | ビルド工程・外部ライブラリなしの静的ファイル。GitHub Pages にそのまま置ける |

## 外部制約（与件）

- 主な端末：Pixel 10（Android、Chrome）。サブ：パパの Windows PC（Chrome / Edge）。
- 配信：GitHub Pages（公開リポジトリ `Ouchi-Calendar`）。データ：GitHub 非公開リポジトリ（`Ouchi-Calendar-data`）。
- ママはスマホ操作に詳しくない → 初期設定（接続コードの貼り付け）はパパが行う。
- 時刻は日本時間のみ（タイムゾーン対応は不要）。

## 成功指標

- ママが **最初の 5 分の説明だけで**、予定の追加・確認・くりかえし予定の「この日だけお休み」を一人でできる。
- 1 か月使い続けられ、家族の予定確認がこのアプリで済む（紙・口頭での確認が減る：主観評価）。
- 同期の不具合で予定が消えた件数 **0 件**。
