## Context（背景・前提）

ママのスマホとパパの PC でデータを共有したい。サーバーは持たず無料にしたい（R-16）。
アプリ本体は公開リポジトリ（GitHub Pages）なので、予定データを同じ場所に置くと誰でも見られてしまう（R-15）。

## Decision（決めたこと）

- 予定データは**別の非公開リポジトリ `Ouchi-Calendar-data` の `data.json`** に置き、ブラウザから GitHub Contents API で読み書きする。
- 認証は **fine-grained personal access token**（対象はデータ用リポジトリだけ、権限は Contents の読み書きだけ）。
  パパが発行し、アプリの「接続コード」にまとめて、ママのスマホに一度だけ貼り付ける。トークンは各端末の localStorage にのみ保存する。
- 同時編集に備え、**レコード（予定・やること・メンバー）単位の last-writer-wins マージ**＋**論理削除**とし、書き込みは sha による楽観ロック（競合時は取り直して再マージ）。
- 端末内に常に全データを持ち、オフラインでも使えるようにする（つながったら同期）。

## Consequences（結果・トレードオフ）

- 無料で GitHub だけで完結。変更のたびにコミットが残るので、**誤操作しても git 履歴から戻せる**（自動バックアップ）。
- データは他人に見えない（非公開リポジトリ＋トークンはそのリポジトリ限定）。
- トークンが端末に平文で保存される。端末を紛失した場合は GitHub でトークンを無効化すれば済む（被害はデータ用リポジトリに限定）。
- トークンには有効期限がある場合があり、切れると同期が止まる → 画面に文字で案内し、パパが再発行する（`docs/setup.md`）。
- 同じ予定を同時に別々の項目で編集すると、後に保存した方の内容だけが残る（家族利用では許容）。
- リアルタイム反映ではない（前面表示中 2 分ごと＋前面に戻った時に取得）。

## Alternatives（検討した他案）

- Firebase（Google）：ログインが簡単でリアルタイム同期できるが、Firebase コンソールの初期設定・セキュリティルール管理が必要。ユーザー判断で GitHub 案を採用。
- 端末内保存のみ：設定ゼロだが、パパが見られず、機種変更・データ削除で消える危険があるため却下。
- 公開リポジトリにデータも置く：家族の予定が公開されるため却下。
